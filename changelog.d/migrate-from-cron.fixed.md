- An upgrade by a user who does not own `data/lamb.db` no longer leaves the data migrations undone. The first `/_cron` request after the code changes runs them, `bin/upgrade` makes that request, for the migrations only, when `SITE_URL` is set, and tarball and Docker upgrades get the same, so none of them needs `bin/lamb migrate` run by hand. Unless it can show that no migration was needed, `bin/upgrade` no longer prints a command to roll back: a failed migration or a failed health check says that the data may be migrated for the new code and points to the error output or the PHP error log.
